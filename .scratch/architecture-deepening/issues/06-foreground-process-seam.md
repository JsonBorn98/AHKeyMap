## Problem

`GetForegroundProcessName` (`HotkeyEngine.ahk:47-52`) calls `WinGetProcessName("A")` directly, so the scope checkers (`MakeProcessChecker`, `CheckIncludeMatch`, `CheckExcludeMatch`) and Path C scope gating are testable only by bypassing the real interface — tests substitute `(*) => true/false` checkers (`hotkey_engine_state.test.ahk:106,115`) instead of exercising the real matching logic.

## Decisions (grilled 2026-09-02, all confirmed)

1. **Mirror the seam that already works**: a `ForegroundProcessHook` global, exactly like `DispatchSendHook` (`Utils.ahk:78-88`). Production: hook is `""` and the function queries `WinGetProcessName("A")`. Tests: set the hook to a scripted process name. Two adapters (prod + test) make the seam real. One seam covers every consumer because they all funnel through `GetForegroundProcessName` — include/exclude checkers, and post-ticket-01 the Path C engine's scope gating (which calls the same checker closures).
2. **Scope discipline**: only the scope-check path. The process picker's `WinGetProcessName(id)` enumeration (`Utils.ahk:202`) is GUI-time listing with no test-double need — untouched.
3. **Single commit**, patch bump, any time.

## Changes by file

- `src/core/HotkeyEngine.ahk` — `GetForegroundProcessName` consults `ForegroundProcessHook` first (mirroring `DispatchSend`'s shape).
- `src/AHKeyMap.ahk` — declare `global ForegroundProcessHook := ""` next to `DispatchSendHook`.
- `tests/support/TestBase.ahk` — reset the hook in `ResetAppState`; add a small `SetForegroundProcess(name)` helper.
