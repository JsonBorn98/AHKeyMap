# 03 — One mapping schema, one path rule

Status: ready-for-agent

Sequencing: land after [01](01-deepen-path-c-engine.md) and [02](02-collapse-config-working-copy.md) — all three touch `HotkeyEngine.ahk` and the test base; landing in order avoids three-way churn.

## Problem

"What a mapping is" is re-stated everywhere instead of owned in one place:

- **Construction** (3 sites): `Config.ahk:105-113` (INI load, with defaults + `Integer()` coercion), `MappingEditor.ahk:127-134` (GUI, the only site with clamping, `:122-125` min 10), `TestBase.ahk:389-399` (`MakeMapping`).
- **Serialization** (2 sites): `SaveConfig` (`Config.ahk:308-316`) and `TestBase.SeedConfigFile` (`:424-433`) each restate the field list.
- **Config records** (2 sites): `LoadConfigData` (`Config.ahk:62-118`) vs `TestBase.BuildConfigRecord` (`:401-413`).
- **Path classification** (3 sites): `DetectHotkeyConflicts` (`HotkeyEngine.ahk:250-257`) and `RegisterMapping` (`:479-509`) independently derive the path and hotkey string — they can silently drift, so conflict reporting can disagree with actual registration. A third restatement is the Path C guard (post-ticket-01: inside `PathCEngine.AddMapping`).

## Decisions (grilled 2026-09-02, all confirmed)

1. **New module**: `src/shared/Schema.ahk`, static-only classes used purely as namespaces (zero state, zero new globals). Include it first in `src/AHKeyMap.ahk`'s list (pure definitions; the `DEFAULT_REPEAT_*` globals are referenced at call time). Update the repo map and include-order list in `AGENTS.md`.
2. **Records stay `Map()`-based** — every reader keeps `["Key"]` access. The schema lives in the constructors, not in a new storage type.

## Interface

```
class Mapping {
    static PATH_A / PATH_B / PATH_C                      ; "A" | "B" | "C"
    static Make(modKey, sourceKey, targetKey, holdRepeat := 0, repeatDelay := "", repeatInterval := "", passthroughMod := 0)
    static Normalize(m)                                  ; whitelist + coerce + defaults + clamp, in place
    static ClassifyPath(m)                               ; the single path rule
    static HotkeyStringFor(m)                            ; the single hotkey-string derivation
    static ToIniPairs(m)                                 ; the single field list for serialization
}

class ConfigRecord {
    static Make(name, processMode, process, excludeProcess, enabled, mappings)   ; owns record shape + ParseProcessList derivation + file path
}
```

Constructor invariants, enforced at **every** construction site including INI load: 7-key whitelist (extras dropped); `Integer()` coercion of `HoldRepeat`/`RepeatDelay`/`RepeatInterval`/`PassthroughMod`; defaults from `DEFAULT_REPEAT_DELAY`/`DEFAULT_REPEAT_INTERVAL`; delay/interval clamped to ≥ 10. **Intentional behavior change**: a hand-edited INI with delay < 10 is now clamped at load (previously only clamped when edited in the GUI). Post-ticket-02, `ConfigStore` also re-normalizes incoming mappings at the chokepoint as a boundary guarantee.

## Consumers rewired

- `Config.LoadConfigData` — per-section `Mapping.Make`/`Normalize` + `ConfigRecord.Make` assembly.
- `Config.SaveConfig` — serializes via `Mapping.ToIniPairs`.
- `MappingEditor.OnEditMappingOK` — builds via `Mapping.Make`, then the store call (per ticket 02).
- `HotkeyEngine.RegisterMapping` — dispatches on `Mapping.ClassifyPath`; Path B combo string via `Mapping.HotkeyStringFor`.
- `HotkeyEngine.DetectHotkeyConflicts` — `hkStr` via `Mapping.HotkeyStringFor`; B/C usage split via `Mapping.ClassifyPath`. Conflict detection can no longer drift from registration: both derive from the same functions.
- `PathCEngine.AddMapping` (post-ticket-01) — guard via `Mapping.ClassifyPath`; its internal entry object is derived from the Map record in one place inside the engine.
- `tests/support/TestBase.ahk` — `MakeMapping`/`BuildConfigRecord` become thin delegates to the real constructors; `SeedConfigFile` writes mappings via `Mapping.ToIniPairs`.
